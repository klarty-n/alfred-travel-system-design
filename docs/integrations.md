# Интеграции и API

## Границы

Внешний API принадлежит поставщику вне TravelTech: перевозчику, агрегатору, booking-платформе или сервису доставки. Alfred обращается к внутренним интерфейсам TravelTech, а его адаптеры к поставщикам. Интерфейс модуля не требует отдельного сервера

При выборе конкретных поставщиков требуется согласовать их ID, полноту данных, лимиты, доступность webhook и срок действия предложений. Обработка рассылок не входит в выбранный вариант: используется API и резервный опрос

| Интерфейс TravelTech | Запрос | Результат |
|---|---|---|
| Status.current | Полный ключ, назначенный поставщик | Подтверждённый статус, времена, поток/ревизия, время наблюдения и проверки |
| Search.alternatives | Потребность перелёта/активности, местоположение, UTC-окно, размер группы и ограничения участников | Кандидаты, условия, цена/валюта, checked_at, expires_at |
| Offers.revalidate | ID предложения, fingerprint прежних условий, актуальные ограничения группы | Полные текущие условия и доступность либо changed/expired/unavailable |
| Booking.tracked_trips | Служебная учётная запись + cursor | Начальная загрузка активных поездок; затем изменения trip_id/source_revision, включая отключение tracking_enabled; следующий cursor |
| Booking.context | trip_id + source_revision + служебная учётная запись | Исходный план при подключении, участники/права, tracking_enabled, факты броней, окна, MCT, багаж и актуальные разрешения на маршрут |
| Booking.action_result | Ссылка на действие и подтверждённый результат изменения брони | Booking-контур обновляет свой контекст и source_revision; Alfred получает факт при синхронизации |

Первоначальный план поступает при фоновом подключении через tracked_trips/context. После подключения Alfred владеет выбранным общим планом. Booking-контур передаёт факты броней и изменения участников/ограничений с монотонной source_revision в пределах поездки; сравнение received_at эту ревизию не заменяет

Одинаковая ревизия должна иметь тот же нормализованный контекст. Старая игнорируется, противоречие требует сверки. При смене current_version во время загрузки контекста применяется повторное чтение и сверка; полный снимок старых броней не заменяет текущий маршрут. Результат бронирования сопоставляется по booking_ref и актуальному элементу

tracked_trips/context являются внутренними портами окружающего TravelTech. Их схемы определяются при подключении конкретного booking-модуля; OpenAPI ниже описывает HTTP API самого Alfred

Для перелёта нужны аэропорты и время каждого участка, подтверждённый статус с основанием/временем проверки, MCT, багаж, места всей группе и разрешения на маршрут/транзит. Для активности нужны место, начало/конец, вместимость, ограничения участников и время на дорогу. Без обязательных данных вариант отклоняется с объяснением

## API Alfred

Точный состав запросов, ответов и ошибок находится в [OpenAPI](../api/openapi.yaml). Контракт является спецификацией, запущенного сервера нет

| Метод | Назначение |
|---|---|
| POST /internal/flight-status-events | Сохранить событие поставщика и запустить обработку |
| GET /trips/{trip_id} | Получить текущий план, состояния рейсов, последствия и свежесть контекста |
| GET /trips/{trip_id}/inbox | Получить сообщения текущего участника с курсором |
| GET /trips/{trip_id}/impacts/{impact_id}/alternatives | Получить состояние поиска и допустимые предложения |
| POST /trips/{trip_id}/selections | Подтвердить предложение с версией и ключом идемпотентности |

Диагностика и безопасный повтор задач относятся к служебному интерфейсу эксплуатации. Он доступен оператору по отдельному разрешению и не входит в бизнес-OpenAPI из пяти операций. Повтор запускает существующий обработчик с исходным основанием; оператор не редактирует payload, версии или маршрут

Inbox возвращается в порядке sequence_no, назначенного под блокировкой поездки. Cursor непрозрачен и привязан к trip/user; даты и UUID не используются как гарантия порядка commit

Пользователь передаёт Bearer-токен TravelTech. Alfred проверяет подпись, issuer, audience и срок; затем членство и право действия. Служебный токен приёма статусов имеет отдельную audience и привязан к provider_id; пользовательским токеном нельзя отправить статус

`trip_id`, `impact_id` и `offer_id` являются идентификаторами, а не разрешениями. Проверка принадлежности выполняется на сервере до выдачи данных или сохранённого результата команды

| Ответ | Значение |
|---|---|
| 200 | Успешное чтение/подтверждение или точный повтор сохранённого события |
| 202 | Событие надёжно сохранено, обработка может продолжаться |
| 401 | Токен отсутствует или недействителен |
| 403 | Участнику запрещено подтверждение либо сервис не соответствует поставщику |
| 404 | Объект отсутствует или относится к чужой поездке |
| 409 | Ключ использован с другим содержимым, версия/состояние изменились, предложение истекло или изменилось |
| 422 | Запрос не соответствует контракту, в том числе содержит неизвестные поля |
| 503 | Повторная проверка или надёжное сохранение временно недоступны |

Время события `observed_at` поступает от источника, `received_at` назначает Alfred. `revision` сравнивается только внутри подтверждённого потока. Для опроса ID строится из идентичности источника и надёжной версии снимка. Если её нет, используется ID устойчивой задачи опроса + хеш ответа: повтор этой попытки узнаваем, а новый цикл опроса может обнаружить возврат к прежнему состоянию. Время или ID цикла не доказывают новизну статуса

`Idempotency-Key` ограничен trip+actor+operation. Сначала проверяется доступ и сохранённый результат; успешный повтор возвращает его даже после истечения первоначального предложения. При повторе с другим телом возвращается 409

Ошибка поиска представлена состоянием `temporarily_unavailable` и пустым списком, отсутствие подходящих вариантов состоянием `none_eligible`. Ответ содержит время последней успешной проверки; при сбое оно может быть null. Просроченные варианты не выдаются как доступные

Цена предложения указывается для всей группы целым числом минимальных единиц валюты и ISO 4217-кодом, аэропорты IATA-кодами, даты ISO 8601, зоны IANA. Входные объекты имеют закрытый список полей; произвольные body и паспортные данные не сохраняются
