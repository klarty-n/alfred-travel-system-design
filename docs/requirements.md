# Требования

## Цель и границы

При задержке или отмене рейса участник должен понять последствия для поездки, получить сохраняемое уведомление и выбрать допустимое изменение общего плана

Alfred отвечает за статусы, последствия, подготовку вариантов восстановления, уведомления и версии плана. Общий модуль подбора TravelTech предоставляет поиск, актуализацию условий и переиспользуемые правила допустимости, расчёта времени и сортировки. Обычный поиск TravelTech и Alfred используют одну реализацию этих правил

Полноценный поиск и изменение бронирований отелей/трансферов остаются в TravelTech. Alfred выявляет необходимые действия с бронями и передаёт их пользователю. В пределах задания он автоматически подбирает альтернативные перелёты и активности

Допущения:

- Все участники одной поездки следуют общему плану; автоматическое разделение группы не предусмотрено
- Багаж и разрешения на маршрут заданы для каждого участника отдельно
- Организатор подтверждает изменения или делегирует это право участнику
- TravelTech предоставляет расписания, условия бронирований, MCT и проверку права на маршрут с указанием основания и срока актуальности
- Если сведения отсутствуют, система показывает неопределённость и не объявляет вариант допустимым
- Общий план может содержать выбранные, но ещё не забронированные элементы; их статус виден участникам

MCT (Minimum Connection Time) означает минимально допустимое время пересадки для конкретных условий. Значение зависит от аэропорта, терминалов, перевозчиков и типа пересадки; универсального MCT нет

## Участники

| Участник | Права |
|---|---|
| Организатор | Просмотр поездки, изменение ограничений, делегирование и подтверждение |
| Участник | Просмотр своей поездки, уведомлений и альтернатив; подтверждение при `can_confirm=true` |
| Поставщик статуса | Передача статусов своего потока без доступа к поездкам |
| Оператор поддержки | Диагностика и повтор обработки; без права менять планы и без паспортных данных |

## Функциональные требования

| ID | Требование |
|---|---|
| F-01 | Сопоставлять событие по полному ключу рейса; неизвестный рейс сохранять как `unmatched` |
| F-02 | Принимать повторы без повторных последствий; одинаковый ID с другим содержимым считать конфликтом |
| F-03 | Применять актуальное подтверждённое состояние, запоминать принятую ревизию при неизменном статусе и сверять спорные данные с назначенным источником |
| F-04 | Рассчитывать последствия для всех элементов общего плана, связанных с изменившимся рейсом |
| F-05 | Сохранять персональное уведомление каждому участнику независимо от доступности устройства и push/email |
| F-06 | При нарушении плана автоматически подбирать альтернативные перелёты или активности. При задержке без нарушения подбирать активности на время ожидания, если подтверждено свободное окно до посадки |
| F-07 | До ранжирования проверять багаж, право на маршрут, места всей группе, пересадки, географию, время и срок предложения по единым правилам TravelTech. Показывать только варианты на актуальном основании |
| F-08 | Перед подтверждением повторно проверять условия предложения, права и версии плана и состояния рейса |
| F-09 | Атомарно сохранять новую версию плана, уведомления и результат запроса; повтор не создаёт версию |
| F-10 | Проверять членство в поездке на каждом пользовательском запросе; одного знания `trip_id` недостаточно |
| F-11 | Показывать недоступность источника, время последней проверки и причины отсутствия допустимых вариантов |
| F-12 | Для отеля и трансфера создавать `booking_action_required`, если требуется уточнение или изменение брони |

## Правила расчёта

- Пересадка допустима, если вылет следующего рейса минус ожидаемое прибытие не меньше `MCT + buffer`; равенство допустимо. Для смены аэропорта отдельно учитывается переезд
- Достижимость отеля, трансфера или активности определяется ожидаемым прибытием, выходом из аэропорта, переездом, запасом и крайним допустимым временем
- При отмене рейса фактическое прибытие не придумывается; зависимые элементы требуют восстановления транспортного участка
- При неизвестных временах или правилах создаётся последствие `needs_information`; неподтверждённая достижимость не считается безопасной
- Позднее прибытие само по себе не означает отмену отеля. Нужны условия конкретной брони
- Активность может заменить другую активность или заполнить ожидание, но не заменяет необходимый перелёт
- Для активности на время ожидания нужны подтверждённое крайнее время явки к выходу на посадку, место ожидания и достижимый путь группы. Активность должна быть доступна в той же зоне аэропорта и не пересекаться с другими элементами плана. Окончание активности плюс время до выхода и запас должны укладываться в крайнее время, равенство допустимо
- При неизвестном или устаревшем времени посадки, отсутствии свободного окна или подходящих активностей остаётся уведомление о задержке. Подбор сам по себе не меняет план
- Норма багажа учитывает подтверждённые платные опции; их стоимость включается в цену предложения. Неизвестная возможность доплаты не доказывает допустимость
- Сохраняемые элементы должны оставаться достижимыми. Изменяемая бронь явно помечается needs_change; необходимость её изменения не скрывается и не выдаётся за подтверждённую услугу
- Вариант должен подходить каждому участнику. Если право хотя бы одного участника воспользоваться маршрутом не подтверждено актуальными данными, система не признаёт предложение допустимым
- Ранжирование использует политику RECOVERY_FLIGHT: время до прибытия от общего earliest_start_at с учётом ожидания, число изменяемых элементов, полная цена предложения для группы, ID по возрастанию. Для RECOVERY_ACTIVITY сначала сумма совпадений тегов с интересами каждого активного участника по убыванию, затем цена и ID по возрастанию
- Первоначальный поиск использует тот же механизм с политикой DISCOVERY и выбранными пользователем критериями. Политика не ослабляет обязательные ограничения; Alfred не реализует собственные копии проверок и сортировки
- Цены сравниваются в валюте поездки. Обязательные сборы и выбранный допбагаж включены, неподтверждённые возвраты и штрафы старых броней из цены не вычитаются
- none_eligible означает отсутствие подходящих вариантов после завершённого поиска у выбранных поставщиков. Неполный поиск явно помечается search_complete=false
- Изменение участников, ограничений или состава плана создаёт новую версию; обновление статуса рейса, ожидаемых времён или подтверждённой границы посадки меняет его `state_version`

## Нефункциональные требования

| ID | Требование и проверяемая цель |
|---|---|
| N-01 | После ответа о приёме событие сохранено; сбой обработчика допускает повтор без потери и дублирования результата |
| N-02 | Все сравнения времени выполняются в UTC; отображение использует IANA-зону каждого места, включая переходы летнего времени |
| N-03 | Паспортные поля запрещены в запросах, хранилище и логах Alfred; тело ошибочного запроса не логируется |
| N-04 | Только HTTPS; пользователь определяется проверенным токеном TravelTech, сервисный отправитель отдельной служебной учётной записью |
| N-05 | p95 от приёма подтверждённого статуса до записи последнего Inbox по событию ≤ 5 с при 10 событиях/с после прогрева и на минутном пике 100 событий/с. Для отдельной отмены на пике с 300 получателями ≤ 30 с до записи всех Inbox |

Нагрузка и время N-05 заданы для приёмки по A-21 и A-50. Это проектные значения, пропускная способность проверяется на реализациии задержка источника измеряется отдельно

Паспортные данные, необходимые для бронирования, остаются в защищённом модуле TravelTech. Он удаляет их, как только они перестают быть необходимы, не позднее завершения поездки; документы не сохраняются для истории или рекомендаций. В Alfred передаются только непрозрачная ссылка на бронь и результат проверки допустимости маршрута
